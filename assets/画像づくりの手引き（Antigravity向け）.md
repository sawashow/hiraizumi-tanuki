# 画像づくりの手引き（Antigravity向け）

このゲーム（平泉タヌキ侍）の絵は、Antigravity が担当する。この文書は、その作業の決まりと、いま直すべき絵の一覧。
何を作るかは [必要な絵の一覧.md](必要な絵の一覧.md)（指示文つき）、絵の基準は [ドット絵基準.md](ドット絵基準.md) にある。

## 担当の分け方

| やること | 担当 |
|---|---|
| 絵を生成する。元絵を `assets/concept/source/` に置く | Antigravity |
| 変換ツール（`tools/make_*.py`・`slice_sheet.py`）で、ゲーム用の絵にして `assets/images/` に置く | Antigravity |
| 変換ツールの直し（切り出す位置・色数・粗さ） | Antigravity |
| 絵の枠の大きさが変わったときの、`config.py` の `ENEMY_FRAMES`・`ENEMY_ART` の数字 | Antigravity |
| 絵に関する文書（この文書・必要な絵の一覧・ドット絵基準）の更新 | Antigravity |
| ゲームの動き（`main.py`・`sprites.py`・`stage.py`・`audio.py`、`config.py` のそのほかの数字） | Claude Code。**Antigravity は、触らない** |

行がそろっていないシート（Gemini の絵は、動きが同じ行に混ざったり、見出しが違ったりする）は、`tools/make_poses.py` で、姿を番号で選んで切り出す。
新しい敵・小物・仕掛けは、絵を置くところまでが Antigravity。動かすのは Claude Code。
絵を置いたら、「何を・どこに置いたか・枠の大きさ・コマ数」を、下の「置いたものの記録」に1行書く。

## 環境

- Python は、Windows 側の仮想環境を使う: `.venv/Scripts/python.exe -X utf8 tools/◯◯.py ...`
  （WSL の `python` では動かない。`-X utf8` を付けないと、日本語のファイル名や出力が化ける）
- 元絵・フォント・試作は `assets/concept/`（git に入らない）。無ければ、Google ドライブの `hiraizumi_concept_年-月-日.zip` を `assets/` に展開する
- 試作や比較の絵は `assets/concept/試作/`・`assets/concept/確認画像/` に置く。`assets/images/` には、採用した絵だけを置く
- ソースは UTF-8・改行 CRLF。文書も同じ

## 1枚の絵を作る手順

1. [必要な絵の一覧.md](必要な絵の一覧.md) の項を読み、「共通の絵柄」＋その項の指示文で、絵を生成する。見本の絵を添付する。
2. 決まった名前で `assets/concept/source/` に置く。置く前に、一覧の冒頭の4点（真っ白な背景・端で切れていない・行の名前・同じ大きさ）を確かめる。
3. 変換ツールで、ゲーム用の絵にする（ツールの使い方は、各ファイルの冒頭）。まず `assets/concept/試作/◯◯/` に出して、見る。
4. **粗さを測る**: `.venv/Scripts/python.exe -X utf8 tools/check_dots.py 出した絵.png`。「○」になるまで、縮尺・色数・粗さを直す。
5. 4倍に拡大した確認画像を作り、主人公（`assets/images/player_00.png`）と並べて、粗さと大きさが合っているかを、目で見る。
6. `assets/images/` に置く。枠の大きさが変わったら、`config.py` の `ENEMY_ART` を合わせる。
7. **テスト**: `.venv/Scripts/python.exe tools/smoke_test.py`（最後に「失敗: なし」と出ること）。
8. 「置いたものの記録」に書く。コミットは、指示されたときだけ。

## 粗さの基準（数字で測る）

`tools/check_dots.py` が、3つの数字を出す。

- **2角**: 2×2 ドットの升目に区切ったとき、1色になっていない升目の割合。0% なら、きれいな2ドット角
- **細線**: 同じ色が、横に1ドットしか続かない所の割合。高いほど、描き込みが細かい
- **色**: 色の数

| 種類 | 基準 | 見本 |
|---|---|---|
| キャラ・敵・小物 | 1ドット単位で描くが、**形は大づかみ**に。細線 70% 以下、16色以下 | 主人公（細線 52%・9色）、烏（56〜67%・10〜13色） |
| 背景（遠景・中景）・タイル・足場 | **2ドット角以上**（2角 15% 以下）、32色以下 | 毛越寺の中景（2角 0%・23色）、毛越寺のタイル（0%・10色） |
| 光（光波） | 決まりなし（輪郭なし。ぼかしてよい） | |
| 文字 | フォントから作る（`tools/make_*text*.py`）。絵としては描かない | |
| 画面いっぱいの一枚絵（題名・地図・結末） | 下の「決めること」を見る | |

### 小さい敵と、飛び道具の見やすさ

小さい敵や、敵が投げる物（矢・扇・玉・花びら）は、見落とすと、理不尽に感じる。**どの面の背景の上でも、見えること**を、先に確かめる
（背景は、朝霧の青白・夏の昼の緑・夕焼けの橙と紫・堂の中の黒と金、の4通り）。

- **敵は、亡霊に見えること。** 顔を描かない（影の中に、光る目だけ）。肌色と、鮮やかな赤を使わない。体の色は、青みの灰・暗い紫・くすんだ藍。
  立ち往生の最初の絵は、表情のある顔と、赤い衣で、生きた人間に見えたので、描き直した。指示文の最初に「生きた人間に見えてはいけません」と書くと、通じた。
- **暗い色だけで描かない。** 体のどこかに、明るい色か、鮮やかな色を入れる（狐火の白い芯、烏のうすい縁取り、弓兵の赤い目）。
- **飛び道具は、明るい縁取りを付ける。** 絵に無ければ、ゲームの側で、白い縁取りを1ドット足す（`sprites.py` の `_rimmed`。弓兵の矢が、これ）。
- **細い物は、太らせる。** 矢の絵は、29×5ドットしかなく、昼の背景で見えなかった。縁取りと、うしろの光の尾を足して、見えるようにした。
  新しく作る飛び道具は、短い辺を6ドット以上にする。
- **置く前に、4つの背景の上に並べて、見る。** 敵や飛び道具の絵を作ったら、各面の空の絵（`bg_sky.png`）の上に重ねた確認画像を作る。
- **予告を、絵で見せる。** 小さい敵ほど、動き出す前の合図（光る・羽ばたく・弓を引く）を、はっきり描く。

「細かい」とは、升目が小さいことではなく、**1ドットの点や線が多いこと**。AIの絵は、鎧の模様・葉の1枚1枚まで描くので、縮めると、ざらざらした面になる。
直し方は、(1) 元絵の指示文で「大きな形だけ。模様は描かない」と頼む、(2) 変換で色数を絞る、(3) 変換で、いったん半分に縮めてから2倍に戻す（2ドット角にする）、の順に試す。

`title.png`（スタート画面）・`stage_map.png`（地図）は、色を絞っていない（4万〜8万色）。

## 決めること（ユーザーに聞く。勝手に決めない）

1. **ボスの粗さを、どちらにそろえるか。**
   - 2ドット角（いまの秀衡・泰衡）: 大きな体が、主人公より粗いドットになる。昔のゲームの、大きなボスの感じ
   - 1ドット単位で、形を大づかみに（主人公と同じ升目。色数を絞り、模様を消す）: 主人公と並んだとき、升目がそろう
   - 秀衡は、2026-10-11 に「ドットが細かい」と言われて、2ドット角に直した。遊んで見た感想は「3面のボスだけ粗い」。2026-10-12 に、1ドット単位へ戻した（**決着: ボスは1ドット単位**）
2. **一枚絵を、ドット絵にそろえるか。** そろえるなら、2ドット角にする。色数は、むやみに絞らない
   （スタート画面の絵は、色を絞ったら、青い狐火が橙に変わった。色を絞るときは、狐火・灯り・月の色が残るかを見る）。
3. **背景を、3面ぶん作り直すか。** 見た目が、かなり変わる（細部がつぶれる）。まず1面だけ直して、見てもらう。

## やってはいけないこと

- 基準に合わない絵を、「とりあえず」で `assets/images/` に置かない。試作の置き場に置く。
- ゲームの中で、絵を引き伸ばして使う前提にしない（足場を横に伸ばしたら、ドットの大きさが不ぞろいになった）。必要な大きさの絵を、作る。
- 1枚の絵を、四角く切って並べない（切り口が見える）。部品ごとに、白い余白で離して描いてもらう。
- 絵の端で、物を切らない。枝のすき間・タイルの上の端に、白を残さない。
- 動きを確かめるために、ゲームを勝手に起動しない（ユーザーが、自分で起動する）。確認は、テストと、静止画で行う。
- コミット・プッシュは、指示されたときだけ。プッシュしたら `tools/backup_concept.py` で、元絵を Google ドライブに置く。

細かい決まりと、その理由（実際に起きた不具合）は、[必要な絵の一覧.md](必要な絵の一覧.md) の「共通の絵柄」にある。
